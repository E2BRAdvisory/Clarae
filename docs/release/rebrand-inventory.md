# Inventario del nome del prodotto (rebrand)

"Nodus" è un **segnaposto**. La scelta del nome definitivo e la sua applicazione sono un'attività da concordare con l'utente: **questo documento non rinomina nulla**, rende solo l'operazione meccanica. Per l'elenco aggiornato dei punti in cui compare il nome:

```sh
scripts/rebrand-inventory.sh            # conteggi per categoria
scripts/rebrand-inventory.sh --files    # con l'elenco dei file di ogni categoria
scripts/rebrand-inventory.sh --name Foo # cerca un altro nome (utile dopo il rebrand per scovare i residui)
```

Lo script è di sola lettura, usa `git grep` (file tracciati e nuovi non ignorati) e non tocca i file generati (`wailsjs/`, `dist/`, lockfile). Fotografia al momento della scrittura (da rieseguire prima di iniziare): circa 360 file e 1.440 righe.

## Procedura proposta

1. Decidere il nome (**Nome**, **N**, **ID** inverso) e quali contratti persistenti mantenere (righe 3, 5, 10, 11, 15).
2. Eseguire `scripts/rebrand-inventory.sh --files > rebrand-before.txt` come riferimento.
3. Applicare in quest'ordine, un commit per riga: 13 (comando esistente) → 14 → 7–9 → 12 → 1, 2, 4, 6 → 10, 3, 15 (contratti, insieme) → 16.
4. `make gen`, `make lint`, `make test`, `make e2e`, `make test-integration`.
5. Rieseguire `scripts/rebrand-inventory.sh --name nodus`: deve restare solo ciò che si è scelto deliberatamente di mantenere (elencarlo in un ADR).
6. Verificare a mano: login desktop e Web UI, link `<scheme>://`, nuova installazione pulita e **aggiornamento** da una installazione esistente (keychain, cartella dati, `.nodus/`).

## Cosa non è nel perimetro automatico

Icone, logo, nome nello store/installer firmato, certificati di firma (il nome entra nell'identità del certificato), dominio e URL pubblici (`nodus.example.com` sono segnaposto negli esempi), testi legali.
